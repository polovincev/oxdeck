# Публикация OxDeck

## 1. Создание репозитория на GitHub

На GitHub нажмите **New repository**, укажите имя `oxdeck` и выберите **Public**. Не добавляйте README, `.gitignore` или лицензию: эти файлы уже есть локально.

Затем выполните в папке проекта:

```bash
git remote add origin https://github.com/polovincev/oxdeck.git
git add .
git commit -m "Initial release"
git push -u origin main
```

## 2. Первый релиз

Перед публикацией настройте постоянный сертификат и три signing secrets по разделу [«Подпись релизов для обновления»](README.md#подпись-релизов-для-обновления). Без них workflow завершится ошибкой и не опубликует неподписанную сборку.

Тег должен совпадать с новой версией в `package.json`. Например, для `1.6.0`:

```bash
git tag -a v1.6.0 -m "OxDeck v1.6.0"
git push origin v1.6.0
```

Тег запустит workflow **Release macOS**. Его прогресс будет виден во вкладке **Actions**, а готовые ZIP-файлы появятся во вкладке **Releases**:

- `arm64` — Mac с Apple Silicon (M1, M2, M3 и новее);
- `x64` — Mac на Intel.

Панель получает обновления только после публикации обычного GitHub Release с тегом `vMAJOR.MINOR.PATCH`. Черновики и prerelease не устанавливаются; не меняйте содержимое уже выпущенного архива. Для следующего обновления выпустите новую версию с тем же сертификатом подписи.

## 3. Следующие версии

Сначала перенесите описание изменений из секции `Unreleased` в новую версию внутри `CHANGELOG.md` и зафиксируйте его. Затем выберите тип версии:

- `patch` — исправление: `0.1.0` → `0.1.1`;
- `minor` — новая обратно совместимая возможность: `0.1.0` → `0.2.0`;
- `major` — несовместимое изменение: `0.1.0` → `1.0.0`.

```bash
git add CHANGELOG.md
git commit -m "docs: update changelog"
pnpm version patch --message "chore: release v%s"
git push origin main --follow-tags
```

`pnpm version` обновит `package.json`, создаст commit и Git-тег. Отправленный тег снова запустит сборку и создаст новую страницу GitHub Release с автоматически сформированными заметками.

## Локальная сборка

```bash
export OXDECK_SIGNING_IDENTITY="OxDeck Updates"
pnpm make:arm64
pnpm make:x64
```

Приложения появятся в папке `out`, а готовые ZIP-файлы — в `out/releases`.

## Подпись macOS

Релизы подписываются собственным сертификатом Code Signing. Он позволяет штатному установщику проверить, что обновление выпустил тот же автор, и не требует платного Apple Developer. Ключ должен оставаться одним и тем же для всех версий и обеих архитектур; храните его резервную копию вне репозитория.

Такая подпись не является Developer ID, сборки не нотарифицированы. При первом запуске может потребоваться разрешение через **System Settings → Privacy & Security → Open Anyway**. Первую сборку с поддержкой обновлений нужно установить вручную поверх старой. Дальнейшие обновления скачиваются внутри панели, а установка начинается только по кнопке в настройках.
